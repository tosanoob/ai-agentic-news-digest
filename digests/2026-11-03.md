## 🔴 Breaking / models / agent frameworks

### 1. LongCat-2.5: Native multimodal model cho long-horizon agents

**Ngày gốc:** 01/11/2026 (bài kỹ thuật); **API available:** 02/11/2026. **Loại:** model release.  
**Nguồn chính thức:** https://longcat.ai/blog/longcat-2.5 · https://longcat.ai/platform/docs/ChangeLog.html

Meituan LongCat công bố model MoE 1,6 nghìn tỷ tham số, khoảng 48 tỷ active/token. Hình ảnh được mã hóa thành discrete tokens đa tầng để backbone xử lý chung với text. Huấn luyện tăng cường long-horizon agentic RL, môi trường có kiểm thử F2P/P2P, các rollout không đồng bộ có lưu và tiếp tục, cùng tối ưu W4A4 trên accelerator. API hỗ trợ các harness như Claude Code, Codex, Hermes.

**Benchmarks do hãng báo cáo:** Terminal Bench v2.1 **88,4** (LongCat-2.0: 70,8); Terminal Bench v4.0 **38,5** (2.0: 3,0); DeepSWE v1.1 **64,6** (2.0: 9,7); MCP Atlas **83,1** (2.0: 61,8). Trên Terminal Bench v4.0, bảng của hãng cho Claude Opus 5 **53,9**, nên không thể tuyên bố LongCat dẫn đầu coding agents. Kết quả phụ thuộc harness, effort, judge, sample và cả điểm đối thủ được trích từ bên thứ ba.

**Technical implications:** Đáng thử cho visual coding, repo agents và workflow nhiều bước; kiểm tra chi phí API, latency, context retention, dữ liệu gửi lên hosted endpoint và khả năng tương thích tool schemas. Không có bằng chứng model weights 2.5 đã được phát hành; không coi nó là open weights.

### 2. DeepSeek dsh-superagent: Proactive coding agent prototype

**Ngày gốc:** 31/10/2026. **Trạng thái:** BACKFILL; bản tin truyền thông 01–02/11. **Loại:** agent framework / GitHub source release.  
**Nguồn gốc:** https://github.com/deepseek-ai/dsh-superagent-prototype

Nhóm DeepSeek Harness công khai mã nguồn MIT của một **research prototype** cho một GitHub repository. Agent nhận sự kiện GitHub (có thể thêm Feishu), lọc người được phép yêu cầu, tạo Ticket và chạy từng tác vụ trong session + thư mục riêng; có web panel cho người review. Các inferred requests mặc định ở chế độ `observe` và chỉ được tự động chấp nhận nếu rule của nhóm cho phép.

**Security caveat quan trọng:** README nói rõ đây **không phải sản phẩm DeepSeek chính thức**, chưa production-ready và không đồng nhất với thiết kế nghiên cứu. Tài liệu executor xác nhận worker chạy lệnh **không cần phê duyệt dưới OS user của operator**; wrappers và blocked commands không tạo security boundary. Do đó chỉ thử nghiệm trên tài khoản/máy cách ly, hạn chế credentials và yêu cầu human review trước merge.

**Technical implications:** Đáng học về event-driven ticket intake, scoped mandates, review-aware delivery và hạn chế attention cost. Không có benchmark đối chứng chính thức về chất lượng coding để so với Claude Code/Codex.

### 3. GitHub Actions: `pull_request_target` bị chặn mặc định từ 02/12 — lịch hoãn được xác nhận

**Ngày công bố:** 02/11/2026. **Loại:** security / breaking CI policy.  
**Nguồn:** https://github.blog/changelog/2026-11-02-pull_request_target-blocked-by-default-december-2/

GitHub thông báo sẽ chặn `pull_request_target` theo mặc định trong **public repositories** từ **02/12/2026**, thay cho mốc 02/11 trước đó. Trước khi enforce có hai đợt brownout **09/11 và 16/11, 16:00–18:00 UTC**. Các Actions event policies có thể explicit allow; private/internal repos không bị ảnh hưởng, cũng không áp dụng GitHub Enterprise Server.

**Technical implications:** `pull_request_target` có thể chạy với context của base repository và secrets, đặc biệt nguy hiểm nếu checkout và chạy code không tin cậy từ fork. Audit các workflows dùng trigger này, test bằng Insights/evaluate mode, chỉ allow những workflows cần thiết và không chạy untrusted PR code trong privileged context.

**Caveat:** Đây là thông báo về thay đổi sắp có hiệu lực, không phải GitHub đã chặn toàn bộ PR workflows ngày 02/11.

## 🏢 Enterprise agent governance

### 4. HKMA Project SAGE: Know Your Agent và delegated authority

**Ngày:** 02/11/2026. **Loại:** policy / enterprise agent governance.  
**Nguồn chính thức:** https://www.hkma.gov.hk/eng/news-and-media/press-releases/2026/11/20261102-4/

Hong Kong Monetary Authority khởi động **Securing Agentic Finance with Governance and Enablement (SAGE)** cùng nhóm chuyên gia ngành tài chính. Bốn trụ cột: ứng dụng B2C/B2B/M2M; agent identity và quyền được ủy quyền (KYA); interoperability; legal/liability/consumer protection.

**Technical implications:** Với agent có quyền giao dịch, cần tách agent identity khỏi user identity, biểu diễn delegation scope, kiểm soát transaction limit, audit và revocation. A2A/MCP có thể là transport/integration nhưng không tự giải quyết legal authority.

**Caveat:** SAGE là sáng kiến nghiên cứu/chính sách, chưa phải tiêu chuẩn KYA bắt buộc hoặc một phiên bản protocol mới.

### 5. LinearB Agentic Studio: Engineering context và metrics grounded qua API

**Ngày:** 02/11/2026. **Loại:** enterprise.  
**Nguồn chính thức:** https://linearb.io/blog/agentic-studio

LinearB ra mắt giao diện truy vấn tự nhiên cho engineering leaders, có biểu đồ, số liệu, widget và date range đi kèm. Hãng nói các con số được lấy từ live public API của LinearB. Người dùng có thể yêu cầu xây metrics/dashboards; các view theo dõi adoption và token/cost của Copilot, Cursor, Claude Code, Amazon Q, Kiro, đối chiếu với cycle time, review time, deployment và rework. Admin giới hạn vai trò được truy cập.

**Technical implications:** Engineering agents cần kết hợp code context với operational metrics, tránh chỉ tối ưu số lượng PR hoặc tokens. Kiểm tra metric provenance, freshness và role-level access khi dùng kết quả cho quyết định.

**Caveat:** Đây là tính năng analytics và context layer, **không phải** benchmark chứng minh coding agents làm tăng productivity; không có controlled experiment mới được hãng công bố trong bài.

## 🔐 Security / GitHub Releases — BACKFILL ngày 28/10

### 6. GitHub AI Scan quét toàn bộ repository (public preview)

**Ngày gốc:** 28/10/2026. **Nguồn:** https://github.blog/changelog/2026-10-28-ai-scan-for-repositories-in-public-preview/

Agentic scanner xem **latest commit trên default branch** và tìm lỗ hổng kể cả ở ngôn ngữ CodeQL chưa hỗ trợ. Findings xuất hiện trong code scanning alerts, tránh lặp những issues CodeQL đã báo; lần scan sau chỉ thêm findings mới, cần rescan để xác nhận fix. Có fixed time budget, tiêu thụ Code Security AI credits.

**Technical implications:** Bổ sung quét toàn codebase cho những nơi PR-only scanning bỏ sót; kiểm tra false positives, ngân sách, thời gian quét, cách xử lý findings và yêu cầu quyền. Private repos thuộc tài khoản cá nhân không được hỗ trợ theo thông báo.

### 7. GitHub quét lỗ hổng riêng của AI applications trên PR (public preview)

**Ngày gốc:** 28/10/2026. **Nguồn:** https://github.blog/changelog/2026-10-28-code-scanning-for-ai-applications-in-public-preview/

GitHub bổ sung PR scanning cho **indirect prompt injection, sensitive information disclosure, excessive agency** và các luồng code để untrusted content tới model có tool/data access. Kết quả hiện trên PR cùng hướng dẫn khắc phục. Yêu cầu GitHub Advanced Security và bật tính năng; chưa hỗ trợ GitHub Enterprise Server.

**Technical implications:** Có thể kiểm tra trust boundaries ở cấp application code trước khi merge, bổ sung cho runtime sandbox và tool authorization. Không đồng nhất với AI Scan toàn repo ở mục 6 hay Copilot Security Extension đã có ledger.

**Caveat:** Static/agentic scan không chứng minh ứng dụng an toàn tuyệt đối; coverage đang mở rộng.

### 8. GitHub context-aware push protection chặn generic secrets (public preview)

**Ngày gốc:** 28/10/2026. **Nguồn:** https://github.blog/changelog/2026-10-28-push-protection-beyond-predefined-secret-patterns/

GitHub bổ sung classifier dựa trên ngữ cảnh code để phát hiện secrets **không có định dạng cố định**. Có thể chặn ngay lúc push; trong kết quả sớm GitHub nói số pushes chứa secret bị chặn tăng **hơn gấp đôi** so với trước. Cần bật cả AI-detected secrets và push protection; mặc định off, tính AI credits khi opt in. Bypass vẫn cần được kiểm soát/ủy quyền.

**Technical implications:** Bảo vệ hữu ích khi coding agents sinh code hoặc config chứa keys nội bộ không khớp regex quen thuộc. Nên kết hợp ephemeral tokens, least privilege và credential rotation.

**Evidence caveat:** Số liệu tăng >2 lần là **vendor-reported early result**, không phải precision/recall độc lập.
